Course topics

AI Agents with Claude Code

Lessons 2–12: ten topic lessons after Lecture 1 (lesson 1), then demo day.

Lesson 2From chatbot to agent

  • Chat vs workflow vs agentWhat an AI agent really is, how it differs from a chat window or a fixed automation, and when each one is the right tool.
  • Opportunity auditStudents score their own tasks to find where automation pays off, and which work must stay human: money, legal commitments, sensitive people decisions.
  • The Claude Code cockpitA first tour of Claude Code: how it works with files, what the permission modes mean, and how to keep it safely inside one project folder.
  • Your first agent: version 0Turn one real job into written instructions and run a first version on real samples. What goes wrong becomes the work of the next lesson.

Lesson 3One agent, one job

  • Anatomy of strong instructionsWhat a good job description for an agent contains: role, audience, steps, decision rules, tone, output format, examples, and what to do when unsure.
  • CLAUDE.md vs SkillsStanding orders the agent always follows versus reusable playbooks it loads only when needed, and how students build their first skill.
  • Knowledge files and memoryGive the agent one source of truth (prices, policies, FAQs) and, for assistants, a memory of what matters between sessions.
  • Scenario drillsRun the agent on realistic, awkward cases, grade the answers and fix the instructions. This training loop is what makes an agent reliable.

Lesson 4Tools, connectors & MCP: your personal chief of staff

  • Tools, connectors and MCPHow agents act on real systems such as Gmail, Calendar, Drive or a spreadsheet, through a common “plug” called MCP, explained without jargon.
  • Safe accessStart read-only, draft instead of send, use test accounts, and learn the “lethal trifecta”: private data, untrusted content and a way to send data out.
  • Build your chief of staffA hands-on morning-brief assistant: today's agenda, clashes, priority emails, draft replies and meeting prep.
  • Cowork or Claude CodeClaude's no-code desktop agent next to Claude Code: what each does well and when to use which.

Lesson 5Agent teams & hard rules

  • Why teamsWhen one agent is not enough, and five simple ways agents can work together: assembly line, dispatcher, committee, manager with specialists, writer with editor.
  • SubagentsSplit a job into specialist roles, each with its own instructions and tools, and read what each one actually did.
  • HooksRules that are enforced automatically, such as “ask before sending anything” or “log every action”. A prompt only asks; a hook enforces.
  • PluginsBundle skills, subagents and hooks into one package you can share, and why you read a plugin before installing it.

Lesson 6Prove it works

  • How agents failThe common failure modes: invented facts or numbers, ignored rules, misused tools, over-confidence, and drift after edits.
  • Eval setsA written set of test scenarios (must-pass, tricky and adversarial) with expected results, run again after every change.
  • Fix until it passesFind the failures, fix the instructions or rules, rerun, and track the pass rate from the first version to the third.
  • “Break my agent” and the cost reviewClassmates try to break each other's agents; then choose the right model for each step and check what a run costs.

Lesson 7Triggers, schedules, n8n & approval gates

  • Triggers and enginesHow an agent starts by itself (a schedule, a form, a message, an email) and the main engines for it: Cowork and Desktop schedules, Claude's cloud scheduled tasks, and n8n.
  • n8n bootcampA hands-on start with n8n, a visual automation tool: triggers, actions, credentials, and a first flow that calls Claude.
  • An email agent on a scheduleAn agent that checks the inbox on a schedule, sorts new mail and saves draft replies, with a person approving every reply.
  • Approval gates and the autopilot ladderDecide per task how much freedom the agent gets: draft only, approve then act, act then report, or fully autonomous.
  • Failure handling and alertsPlan for the day something breaks: error alerts, retries, and a clear answer to “what happens when it fails?”

Lesson 8The front desk: WhatsApp & Telegram

  • Channel architectureHow a message travels from a chat channel to the agent and back, with knowledge, tools, a hand-off to a human, and a log.
  • WhatsApp policy and privacyWhat WhatsApp allows for business bots, how Israeli privacy rules affect customer messages, and why the bot should say it is an AI (not legal advice).
  • Build the front deskA customer-service agent built on Telegram first (quick to set up), then connected to WhatsApp using a test number.
  • Live testClassmates play customers with scenario cards: price questions, complaints, off-topic requests, injection attempts, slang.

Lesson 9Social, content & lead engines

  • The content engineFrom an idea to a content calendar and drafted posts, with a person approving everything before it goes public.
  • Brand voice and the writer–editor pairTeach the agent your voice, then pair a writer agent with an editor agent that checks tone and facts.
  • Lead engine and listeningScore incoming leads and draft follow-ups; read comments and suggest replies. A person approves every outgoing message.
  • Platform rules and the weekly reportWhat the platforms allow (no fake engagement, no scraping, disclose AI where required) and a small agent that summarizes the week.

Lesson 10Security & safe autonomy

  • The five threats to an agentPrompt injection, data leakage, excessive agency, leaked secrets and untrusted plugins or tools, with real-world examples.
  • Red-team labAttack your own agent with poisoned emails, PDFs, web pages and chat messages, then patch what breaks.
  • HardeningApply a 12-point safety checklist and record each agent's owner, purpose, data, permissions and approvals.
  • Incident drillPractice the response to a leaked key: pause, revoke, read the logs, fix, test and resume.

Lesson 11Go live 24/7 in the cloud

  • Where should my agent live?The options for running an agent without your laptop: Claude's cloud schedules, n8n, an always-on machine, or Anthropic's hosted agents.
  • GitHub in 15 minutesA free GitHub account and a private folder in the cloud: the agent's home, which Claude's cloud tasks need, plus a saved version history.
  • The 24/7 checklistWhat a reliable agent needs: safe secrets, alerts, spend caps, retries and a version history.
  • Launch labDeploy your agent (for example an email agent that runs hourly in the cloud), break it on purpose, measure the cost per run and write a one-page runbook.
  • Demo prepPrepare the story and the numbers (hours saved, pass rate, cost, return on investment) for demo day.

Lesson 12Demo day

  • Format and rubricHow the day runs and what the panel looks for: a live agent, evidence of quality, safety, business value and a clear story.
  • Live demosEach student pitches for 6 minutes, demonstrates live for 3 and answers questions for 2.
  • Awards, feedback and what comes nextPeer feedback, awards and certificates, plus next steps for keeping an agent healthy and growing.
